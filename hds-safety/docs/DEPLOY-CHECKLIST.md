# 운영 시작 전 확인 목록

배포 방법은 [README](../README.md) 5~8번, 화면 사용법은 [사용 설명서](USER-GUIDE.md)를 보십시오. 위에서부터 차례로 체크합니다.

## 1. 계정

- [ ] 앱을 올릴 계정을 정했다. 개인 계정이 아니라 안전경영지원실 공용 계정(가능하면 Google Workspace)이다.
- [ ] 그 계정에 2단계 인증이 켜져 있고, 비밀번호를 아는 사람이 정해져 있다.
- [ ] Workspace 계정이면 웹앱을 "모든 사용자"에게 공개할 수 있는지 Workspace 관리자에게 확인했다.
- [ ] 사업장 수와 독촉 메일을 생각할 때 하루 메일 한도(개인 100명 / Workspace 1,500명)로 충분하다.

## 2. 코드 올리기

방법 하나만 고릅니다. 한 프로젝트에 섞지 않습니다.

- [ ] 개발 담당자가 `paste/` 를 최신 `gas/` 로 다시 만들어(`npm run paste`) 검사(`npm run check`, `npm run test:paste`)를 통과시킨 뒤 함께 전달했다.
- [ ] (A) 붙여넣기: 편집기 파일 목록이 `appsscript.json`, `Code.gs`, `Index.html`, `Styles.html`, `App.html`, `App2.html`, `App3.html`, `FormsData.html` 8개이고, 각각 `paste/` 의 같은 이름 파일 내용으로 통째로 바꿨다.
- [ ] (A) 를 `gas/` 파일로 했다면: `gas/` 의 파일(현재 `appsscript.json` + `.gs` 10개 + `.html` 12개)을 같은 이름으로 만들었고, 기본 `Code.gs` 는 지웠다.
- [ ] (B) clasp: Apps Script API 를 켰고, `.clasp.json` 에 스크립트 ID 를 넣었고, `npm run push` 가 오류 없이 끝났다.
- [ ] `Code.gs`(붙여넣기)와 `Config.gs` 등(`gas/`)이 한 프로젝트에 함께 있지 않다.
- [ ] `appsscript.json` 의 시간대가 `Asia/Seoul` 이다.
- [ ] 편집기에서 모든 파일을 저장했고, 저장할 때 문법 오류가 나지 않았다.

## 3. setup (웹앱 배포보다 먼저)

- [ ] 편집기에서 `Code.gs`(붙여넣기) 또는 `Setup.gs`(`gas/`·clasp)를 연 상태로 `setup` 을 실행하고 권한을 승인했다.
- [ ] 실행 로그의 관리자 `admin` 임시 비밀번호를 안전한 곳에 적었다.
- [ ] 드라이브에 `HDS 안전장부 DB` 시트와 `HDS 안전장부 파일` 폴더가 생겼다.
- [ ] 프로젝트 설정 → 스크립트 속성에 `DB_ID`, `FOLDER_ID` 가 있다.

## 4. 웹앱 배포

- [ ] 배포 → 새 배포 → 웹 앱, **실행: 나**, **액세스: 모든 사용자**로 배포했다.
- [ ] 웹앱 주소(`…/exec`)를 기록해 두었다. 이 주소는 앞으로 바꾸지 않는다(업데이트는 배포 관리 → 새 버전).
- [ ] 구글에 로그인하지 않은 시크릿 창에서 주소를 열어 로그인 화면이 나온다(시크릿 창은 브라우저 저장소가 막혀 로그인 뒤 바로 튕길 수 있으니, 로그인 확인은 일반 창에서 한다).
- [ ] 휴대폰(LTE)으로도 열린다.

## 5. 관리자 설정

- [ ] `admin` 으로 로그인해 비밀번호를 바꿨다.
- [ ] 관리자 계정을 한 명 더 만들었다(비밀번호 분실 대비).
- [ ] 설정: 회사명이 맞다.
- [ ] 설정: 본사 메일(사고 즉시 알림·매일·매주 요약 받을 주소)을 넣었다.
- [ ] 설정: 메일 종류별 켜기·끄기, 독촉 시점, 일일점검 마감 시각, 월간보고 마감일을 정했다.
- [ ] 설정: 필수 양식 기본값과 하절기 폭염 점검 달(기본 4~9월)을 확인했다.
- [ ] 본사 담당(hq)·열람(viewer) 사용자를 만들고 각자 첫 로그인 후 비밀번호를 바꾸게 안내했다.

## 6. 트리거

- [ ] 설정 → 트리거 설치를 눌렀다(또는 편집기에서 직접 추가).
- [ ] 편집기 트리거 화면에 `cronDaily`(매일 오전 8시대)와 `cronWeekly`(월요일 오전 8시대)가 하나씩만 있다.
- [ ] 트리거 소유자가 앱을 올린 계정이다.

## 7. 사업장

- [ ] 사업장 ID 규칙을 정했다(영문 대문자·숫자 2~8자, 예: `S001`). 한번 정하면 바꾸지 않는다.
- [ ] 모든 사업장을 등록했다: 이름·유형·지역·고객사·근무조.
- [ ] 사업장마다 담당자 이름·**이메일**·전화를 넣었다(요청·반려·독촉 메일 수신).
- [ ] HEC 평가 대상 사업장은 대상 표시와 최근·다음 평가일을 넣었다.
- [ ] 사업장별 필수 양식이 맞다(다르면 사업장 상세에서 수정).
- [ ] 인원 명부를 넣었거나, 사업장 담당자가 넣기로 했다.
- [ ] PIN 을 쓸지 정했고, 쓰면 사업장마다 정했다.

## 8. 시범 운영(사업장 한 곳으로 처음부터 끝까지)

- [ ] 사업장 링크를 휴대폰으로 열어 작성자 이름을 넣고 들어갔다.
- [ ] 일일점검을 쓰다가 닫았다가 다시 열어 임시저장이 남아 있다.
- [ ] 주의·불량 항목에 사진을 붙여 제출했다 → 조치대장에 조치가 생겼다.
- [ ] 드라이브 `HDS 안전장부 파일` 폴더에 사진이 올라갔다.
- [ ] 본사 검토함에서 그 기록을 **반려**했다 → 사업장 담당자 메일이 왔고, 사업장 홈에 반려 기록이 보인다.
- [ ] 사업장에서 고쳐 다시 제출했다 → 본사에서 **확인**했다 → 기록이 잠겼다.
- [ ] 사업장에서 조치를 조치중 → 완료(조치 후 사진)로 보고했다 → 본사에서 확인했다.
- [ ] 재해·사고 보고서 속보 단계를 제출했다 → 본사 메일로 알림이 왔다.
- [ ] 취합 현황판에 시범 사업장 칸이 상태대로 표시된다.
- [ ] 요청을 하나 보냈다 → 담당자 메일이 왔다 → 사업장 받은 요청에 보이고 열람 표시가 본사에 보인다.
- [ ] 기록 조회에서 엑셀과 구글 시트 내보내기가 된다.
- [ ] 기록 하나와 빈 양식 하나를 인쇄(PDF 저장)했다.
- [ ] 분석 화면이 시범 데이터로 그려진다.
- [ ] 시범 데이터를 남길지 정했다. 지운다면 기록 상세에서 삭제한다.

## 9. 보안

- [ ] 예시 데이터를 불러온 적이 있다면, 실제 사업장 등록 전에 데이터 비우기를 했다.
- [ ] DB 시트·파일 폴더를 앱 운영 계정 밖에 편집 공유하지 않았다.
- [ ] 스크립트 속성에 `ALLOW_SETUP` 이 남아 있지 않다(넣었다면 setup 실행 뒤 지웠다).
- [ ] 사업장 링크·QR 은 담당자에게 개별로 보냈다(단체방·게시판 금지).
- [ ] 링크가 샐 때 쓸 링크 재발급 방법을 본사 담당자가 안다.
- [ ] (선택) AI 요약을 쓰면 `ANTHROPIC_API_KEY` 를 스크립트 속성에 넣었고, Claude Console 에 사용 한도를 걸었다.

## 10. 운영 인계

- [ ] 사용 설명서를 본사 담당자와 사업장 담당자에게 나눠 줬다(사업장용은 뒷부분).
- [ ] 백업 방법을 정했다: 정기적으로 DB 시트 파일 → 사본 만들기(예: 매월 초).
- [ ] 업데이트 절차(새 배포가 아니라 배포 관리 → 새 버전)를 담당자가 안다.
- [ ] 앱 운영 계정·웹앱 주소·관리자 계정 목록을 정해진 곳에 기록했다.

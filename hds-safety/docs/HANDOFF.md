## 1. 이게 뭔가
HDS(주) 안전경영지원실이 표준 안전보건 양식(F01~F10, N1~N4)을 사업장에 **배포**하고, 사업장이 휴대폰으로 작성·제출한 것을 **취합**하고, 본사가 **분석**하는 Google Apps Script 웹앱.
- 설계 계약서: `SPEC.md` (데이터 모델·API·화면·디자인 규칙의 정본). 모든 수정은 SPEC 을 따른다.
- 디자인 규칙: taste-skill 앱 화면 규칙(`dev/AGENT-BRIEF.md` 의 마크업 계약 + SPEC §9) + HDS CI(네이비 #223189, 레드 #E03024, 잉크 #14183c, Paperlogy 제목).
- **최우선 요구: 구글 앱스 스크립트 편집기에 복사·붙여넣기로 설치** — `paste/` 8개 파일(SPEC §12).

## 3. 명령
```
cd hds-safety
npm test            # 서버 시나리오 시험 (Node, 의존성 없음)
npm run paste       # gas/ → paste/ 붙여넣기 묶음 다시 만들기 (gas/ 고친 뒤 반드시)
npm run check       # 붙여넣기 규칙 검사 ('<?'·'?>', import/require, 로드 순서, paste 최신 여부)
npm run test:paste  # paste/Code.gs 만으로 서버 시험
npm run build       # dist/preview.html (모의 GAS 내장 단일 HTML, ?demo=1 → admin/hds1234 자동 로그인 + 예시 데이터)
npm run e2e         # Playwright E2E (Chromium 필요)
```
수정 규칙: gas/ 만 고친다(paste/·dist/ 는 생성물). 고친 뒤 `npm run paste && npm run check && npm test && npm run test:paste && npm run build && npm run e2e`.

## 4. 감사 후 고친 것 (요약)
- [심각] GAS iframe 안 '#/…' 링크가 최상위 창을 이동시키던 문제(`<base target="_top">` 제거).
- 보안: setup·트리거 함수는 소유자/실제 트리거만 실행, 사업장 세션의 본사 전용 단계 제출 거부, 쓰기 요청 자동 재시도 중단(중복 기록 방지), 저장소 차단 브라우저에서 로그인 유지.
- 서버: 분석 시트 재구축 스택 오버플로·속도(나눠서 이어 쓰기), 메일 발송은 잠금 밖, 1건 조회 시 데이터 읽기 45MB→2.6MB, 뷰 시트 셀 한도 절약, N3 보류·불허 시 즉시 종결.
- 양식 엔진: N3 안전조치 전부 '해당없음'·가스 기준 벗어남 차단, 서명 칸 필수 검증, 숫자 조건 필수(F07·F06·F09), 정수 칸, F07 전일 미결 조치 표시, N1 회차별 기록 안내.
- 분석: 재해율 분모(부분 보고 월), 직전 N개월 비교 구간, 이중 반올림, 반려 기록 제외, 앱 사용 시작 전 기간 제외, 종료 사업장 처리, 기한경과 정의 통일, 카드 빈 공간 대부분.
- 본사 화면: 취합 현황판 분기 보기에서 기한 지난 요청 미제출이 숨던 문제, 조치대장 담당자 잘림, 휴대폰 두 줄 행, 목록 50행+더 보기, 표 머리 고정.

## 5. 남은 일
1. **실제 구글 계정에 붙여넣기 설치 후 스모크 시험** — 지금까지는 모의 GAS(dev/gas-mock.js)에서만 검증. 실제 iframe·메일·트리거·xlsx 내보내기·Paperlogy 글꼴 확인.
2. (완료) 끊겼던 감사 4개 영역은 2차 감사로 다시 돌렸고, 남은 경미 6건(서버 중복 제출 차단, 양식 목록 휴대폰 두 줄 행, 기록 상세 표 여백, 오프라인 하단 줄과 키보드, 휴대폰 검토함 고정 버튼·목록 복귀, 예시 데이터 검증 위반)도 고쳐 재검증함. AI 요약 기능은 요청 범위가 아니라 제거함. 남은 참고: API 를 직접 부르는 클라이언트가 period 값을 조작하면 중복 검사를 피할 수 있음(정상 화면은 영향 없음).
3. 경미 잔여: KPI 빈 값 대시 크기 화면별 차이(JsHq 일부), 양식 목록(#/forms)·분석 표의 휴대폰 두 줄 행 미적용, 사업장 홈 '할 일' 목록 상한 없음, 첫 화면 boot 응답이 기록 수에 비례(클라이언트 boot days 줄이고 긴 기간은 records.index 로), JsHq 의 U+FEFF 리터럴, FormsData 한 줄 47만 자.
4. 양식 내용: F08B '기한 상태'는 사용자가 직접 고름(자동 판정 아님 — 안내문은 사실대로 고침), 직무 태그로 숨긴 항목 우회 없음, 용어 정리('ACT','MU' 등), N3 묶음별 1칸만 확인해도 통과·측정 표 수치 열 없음, **법령 조문 번호는 법무 확인 필요**.
5. 고객 결정 필요(현재 기본값으로 동작): F07 본사 확인 대상 여부(기본: 불량·사고 있는 것만), 재해율 정의(ΣA02 ÷ 사업장별 평균 월말 재적 합 × 100), 폭염 시즌 4~9월, 제출 기록 재편집은 [수정 제출]만, FORMS-REVIEW.md 의 결정 13개, 앱 사용 시작일 설정.

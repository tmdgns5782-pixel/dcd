# HDS 안전장부

HDS(주) 안전경영지원실(본사)이 표준 안전보건 양식을 사업장에 **배포**하고, 사업장이 휴대폰으로 작성·제출한 기록을 한곳에 **취합**하고,
사업장·기간별로 **분석**하는 웹앱입니다. Google Apps Script 로 만들어 회사 구글 계정 하나에 올리면 되고, 데이터는 그 계정의
구글 시트와 드라이브에 쌓입니다. 사업장 담당자는 구글 계정 없이 본사가 보낸 사업장 링크(또는 QR)로 들어와 씁니다.

- 사용 설명서(본사·사업장 담당자용): [docs/USER-GUIDE.md](docs/USER-GUIDE.md)
- 운영 시작 전 확인 목록: [docs/DEPLOY-CHECKLIST.md](docs/DEPLOY-CHECKLIST.md)
- 양식 6~10번·N1~N4 검토·보완 내역: [docs/FORMS-REVIEW.md](docs/FORMS-REVIEW.md)
- 붙여넣기 설치 파일 6개: [paste/](paste/) — 설치 순서는 [5. 배포 방법 (A)](#5-배포-방법-a-붙여넣기)
- 설계 계약서(개발자용): [SPEC.md](SPEC.md)

## 1. 누가 무엇을 하나

| 역할 | 들어오는 방법 | 할 수 있는 일 |
|---|---|---|
| 본사 관리자(admin) | 웹앱 주소 + 아이디·비밀번호 | 전부. 사업장·사용자 관리, 요청 배포, 검토(확인·반려), 분석, 설정 |
| 본사 담당(hq) | 같음 | 관리자와 같음. 단, 사용자 관리·설정은 못 함 |
| 본사 열람(viewer) | 같음 | 기록 읽기와 분석만 |
| 사업장 | 사업장 링크(`…/exec?s=<사업장 토큰>`) 또는 QR + 작성자 이름(+ 사업장 PIN) | 자기 사업장 기록 작성·제출, 조치 보고, 받은 요청·공지 확인, 인원 명부 관리 |

본사 사용자는 같은 Google Workspace 도메인이면 "구글 계정으로" 로그인도 됩니다(사용자 화면에 등록한 이메일과 같아야 함).

## 2. 화면 구성

**본사(데스크톱 우선)** — 왼쪽 사이드바 순서

| 묶음 | 화면 | 이 화면이 답하는 질문 |
|---|---|---|
| 현황 | 종합 현황 | 오늘 손봐야 할 사업장·건은 무엇인가 |
| | 취합 현황 | 이번 기간 누가 무엇을 안 냈나 (사업장 × 양식 현황판) |
| | 검토함 | 무엇을 확인·반려해야 하나 |
| | 배포·요청 | 보낸 요청이 얼마나 돌아왔나 |
| 기록 | 양식 | 표준 양식 목록, 새로 쓰기, 빈 양식 인쇄 |
| | 기록 조회 | 기록 찾기·필터·엑셀/시트 내보내기·일괄 인쇄 |
| | 조치대장 | 기한이 지났거나 다가오는 조치는 |
| 분석 | 분석 | 사고·위험이 어디서 늘고 있나 (개요, 재해·아차, 위험성평가, 일일점검, 교육·훈련, 조치 이행, HEC 준비도, 사업장 비교, 양식별 분석) |
| 관리 | 사업장 | 사업장 정보·링크·QR·PIN·인원·필수 양식 |
| | 사용자 | 본사 계정 관리(관리자만) |
| | 설정 | 회사·메일·독촉·필수 양식 기본값·뷰 재구축·트리거·시스템 정보(관리자만) |

**사업장(휴대폰 우선)** — 아래쪽 탭

| 화면 | 내용 |
|---|---|
| 홈(오늘 할 일) | 받은 요청·정기 마감·반려된 기록·미결 조치를 마감순으로. 큰 버튼 두 개: 오늘 일일점검, 사고·아차 보고 |
| 받은 요청 | 본사 요청·공지, 열람 표시, 첨부 내려받기 |
| 기록 | 우리 사업장 기록 |
| 조치 | 우리 사업장 조치(조치중·완료 보고, 사진) |
| 사업장 정보 | 사업장 정보와 인원 명부 |

양식 작성 화면은 본사·사업장이 같이 씁니다(본사는 대리 입력).

## 3. 표준 양식

양식 정의는 `gas/FormsData.html` 하나에 들어 있고, 앱이 이 정의로 입력 화면·검증·계산·조치 자동 등록·인쇄를 만듭니다.
원본 파일은 `ref/forms-original/` 에 있습니다. 1~5번은 HDS 직원이 만든 원본을 참고해 옮겼고, 6~10번은 내용·디자인을 보완했으며,
N1~N4는 새로 만들었습니다. 고객사(HEC) 안전평가 항목은 N4 와 분석의 HEC 준비도 기준입니다. 보완 내역은 [docs/FORMS-REVIEW.md](docs/FORMS-REVIEW.md).

| 코드 | 원본 번호 | 양식 | 주기 | 기본 마감 | 단계 |
|---|---|---|---|---|---|
| F01 | 1 | 위험성평가서 | 매년 | 직전 평가일 + 1년 | 평가 실시 → 결과 공유 → 본사 검토 |
| F01B | 1-④ | 위험성평가 근로자 참여 회의록 | 발생 시 | 발생 후 3일 | 한 번에 제출 |
| F02 | 2 | 열린안전소통센터 보고서(아차사고·제안·의견청취) | 발생 시 | 발생 후 7일 | 접수 → 소장 확인 → 채택·회신 → 종결 |
| F03 | 3 | 위험성평가 요청서 | 발생 시 | 사유 발생 시 바로 | 요청 → 본사 처리 |
| F04 | 4 | 재해·사고 보고서 | 발생 시 | 속보는 발생 후 1일 | 속보 → 조사·원인 → 재발방지 대책 → 종결 |

- 단계가 있는 양식은 단계마다 제출합니다. 첫 단계만 낸 상태도 본사에 "1단계 보고"로 보입니다.
- 사업장마다 꼭 내야 하는 정기 양식(필수 양식)은 **설정**의 기본값(처음 값: F07, F09, F01, N1, N2, N4, F08B, F10B, 그리고 4~9월에는 F06 — 4월은 시즌 전 점검)을 따르고,
  사업장 화면에서 사업장별로 바꿀 수 있습니다. 취합 현황판과 독촉 메일은 이 목록을 기준으로 합니다.

## 5. 배포 방법 (A) 붙여넣기

컴퓨터에 아무것도 설치하지 않고 브라우저만으로 올리는 방법입니다. **처음 설치는 이 방법을 권합니다.**
붙여넣을 파일은 `paste/` 폴더의 6개입니다. `gas/` 의 파일을 종류별로 합쳐 둔 것이라 내용은 같습니다.

| `paste/` 파일 | 편집기에서 만들 파일 | 만드는 방법 | 들어 있는 것 |
|---|---|---|---|
| `appsscript.json` | `appsscript.json` | 이미 있음(아래 3단계에서 보이게 함) | 시간대·권한·웹앱 설정 |
| `Code.gs` | `Code.gs` | 이미 있음(새 프로젝트의 기본 파일) | 서버 코드 전부 |
| `Index.html` | `Index` | 파일 옆 `+` → HTML | 화면 뼈대 |
| `Styles.html` | `Styles` | 파일 옆 `+` → HTML | 디자인 |
| `App.html` | `App` | 파일 옆 `+` → HTML | 화면 코드 |
| `FormsData.html` | `FormsData` | 파일 옆 `+` → HTML | 표준 양식 정의 |

`paste/붙여넣기-안내.txt` 는 이 절차를 줄인 메모입니다. 편집기에 붙여넣지 않습니다.

**준비**

- 앱을 올릴 구글 계정. 개인 계정보다 **안전경영지원실 공용 계정**(Google Workspace 권장)을 쓰십시오.
  DB 시트·사진 폴더가 이 계정 드라이브에 만들어지고, 메일도 이 계정 이름으로 나갑니다. 담당자가 바뀌어도 계정은 남아야 합니다.
- 파일 내용은 메모장·VS Code 같은 **텍스트 편집기**로 열어 전체 선택(Ctrl+A) → 복사(Ctrl+C)합니다.
  워드·한글 같은 문서 프로그램을 거치면 따옴표가 바뀌어 동작하지 않습니다.

**순서**

1. 그 계정으로 <https://script.google.com> 에 들어가 **새 프로젝트**를 만듭니다.
2. 왼쪽 위 "제목 없는 프로젝트"를 눌러 이름을 `HDS 안전장부` 로 바꿉니다.
3. 매니페스트를 보이게 합니다: 왼쪽 톱니바퀴 **프로젝트 설정** → **"편집기에서 'appsscript.json' 매니페스트 파일 표시"** 체크 → 왼쪽 `< >` **편집기**로 돌아옵니다.
4. `appsscript.json` 을 열어 내용을 모두 지우고 `paste/appsscript.json` 내용을 붙여넣습니다.
5. `Code.gs` 를 열어 기본 내용(`function myFunction() {…}`)을 모두 지우고 `paste/Code.gs` 내용을 붙여넣습니다.
6. **파일** 옆 `+` → **HTML** → 이름에 `Index` 를 넣습니다(`.html` 은 자동으로 붙음). 기본 내용을 모두 지우고 `paste/Index.html` 내용을 붙여넣습니다.
7. 같은 방법으로 HTML 파일 `Styles`, `App`, `FormsData` 를 만들고 각각 `paste/Styles.html`, `paste/App.html`, `paste/FormsData.html` 내용을 붙여넣습니다.
   - 이름은 대소문자까지 똑같이 맞춥니다. `Index.html` 이 이 이름으로 나머지 파일을 불러옵니다.
   - `App.html` 과 `FormsData.html` 은 큰 파일입니다. 붙여넣는 동안 편집기가 멈춘 듯 보여도 기다립니다.
8. 저장합니다(Ctrl+S, 또는 위쪽 디스크 아이콘). 왼쪽 파일 목록이 `appsscript.json`, `Code.gs`, `Index.html`, `Styles.html`, `App.html`, `FormsData.html` 6개인지 확인합니다.
   저장할 때 문법 오류가 나면 그 파일이 덜 붙여넣어진 것입니다. 내용을 모두 지우고 다시 통째로 붙여넣습니다.
9. 왼쪽에서 `Code.gs` 를 연 상태로, 위쪽 함수 목록에서 **`setup`** 을 고르고 **실행**을 누릅니다.
   함수 목록에는 지금 열려 있는 파일의 함수만 나옵니다.
10. "승인 필요" 창 → **권한 검토** → 계정 선택. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급** → **HDS 안전장부(으)로 이동** → **허용**.
    직접 만든 스크립트라서 나오는 화면입니다. 요청하는 권한과 이유:

    | 권한 | 이유 |
    |---|---|
    | 스프레드시트 | DB(구글 시트) 읽기·쓰기 |
    | 드라이브 | 사진·서명·첨부·내보내기 파일 저장 |
    | 메일 보내기 | 요청·반려·독촉·사고 알림 메일 |
    | 트리거 관리 | 매일·매주 자동 작업 설치 |
    | 외부 서비스 연결 | AI 요약(키를 넣었을 때만 사용) |
    | 이메일 주소 보기 | "구글 계정으로" 로그인 |

11. 아래 **실행 로그**에 나온 관리자 아이디 `admin` 과 **임시 비밀번호**를 안전한 곳에 적어 둡니다. 이 비밀번호는 처음 한 번만 표시됩니다.
    setup 은 다시 실행해도 이미 만든 DB·폴더·관리자는 건드리지 않습니다.
12. 오른쪽 위 **배포** → **새 배포** → 유형 선택(톱니바퀴) → **웹 앱**.
    - 설명: `v1.0.0` 처럼 버전
    - **실행: 나**(Execute as: Me) — 앱을 올린 계정 권한으로 시트·드라이브·메일을 씁니다
    - **액세스: 모든 사용자**(Who has access: Anyone) — 사업장 담당자가 구글 로그인 없이 들어오려면 꼭 이 값이어야 합니다
13. **배포** → (요청하면 액세스 승인) → **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다. 이 주소가 앱 주소입니다.
    Google Workspace 계정이면 `https://script.google.com/a/macros/<도메인>/s/…/exec` 모양일 수 있습니다.
14. 구글에 로그인하지 않은 시크릿 창에서 이 주소를 열어 로그인 화면이 나오는지 확인한 뒤 [7. 처음 설정](#7-처음-설정)으로 갑니다.

**`gas/` 파일을 하나씩 붙여넣어도 됩니다.** `paste/` 대신 `gas/` 의 파일(현재 `appsscript.json` + `.gs` 10개 + `.html` 12개)을
같은 이름으로 하나씩 만들어 붙여넣어도 똑같이 동작합니다. `.gs` 는 `+` → **스크립트**, `.html` 은 `+` → **HTML** 로 만들고(이름은 확장자 없이),
`appsscript.json` 은 위 3~4단계처럼 바꾸고, 기본 `Code.gs` 는 이름 옆 ⋮ → **삭제**합니다. setup 은 `Setup.gs` 를 연 상태에서 실행합니다.
파일이 많아 빠뜨리기 쉬우니 처음 설치는 `paste/` 를 권합니다.

> 한 프로젝트에 두 방식을 섞지 마십시오. `paste/` 의 `Code.gs` 와 `gas/` 의 `.gs` 파일이 함께 있으면 같은 코드가 두 번 들어가 엉킵니다.
> 방식을 바꾸려면 기존 파일을 모두 지우고 새로 붙여넣습니다(`appsscript.json` 은 남김). 데이터는 시트·드라이브에 있어 그대로 남습니다.

## 6. 배포 방법 (B) clasp

구글의 명령줄 도구 clasp 로 `gas/` 폴더를 통째로 올리는 방법입니다. 코드를 자주 고치는 개발 담당자에게 편합니다.
Node.js 20 이상이 필요합니다.

1. Apps Script API 를 켭니다: 앱을 올릴 계정으로 <https://script.google.com/home/usersettings> → **Google Apps Script API** 사용 설정.
2. clasp 를 설치합니다.

   ```bash
   npm i -g @google/clasp
   ```

3. 앱을 올릴 계정으로 로그인합니다(브라우저가 열림).

   ```bash
   clasp login
   ```

4. <https://script.google.com> 에서 **새 프로젝트**를 만들고 이름을 `HDS 안전장부` 로 바꿉니다.
   **프로젝트 설정** → **스크립트 ID** 를 복사합니다.
5. 저장소 폴더(`hds-safety/`)에서 예시 파일을 복사해 `.clasp.json` 을 만듭니다.

   ```bash
   cp .clasp.json.example .clasp.json
   ```

   `.clasp.json` 의 `<여기에 스크립트 ID>` 를 복사한 ID 로 바꿉니다. `rootDir` 은 `gas` 그대로 둡니다.

   ```json
   {"scriptId":"1AbC…xyz","rootDir":"gas"}
   ```

6. `gas/` 의 파일을 올립니다. 매니페스트를 덮어쓸지 물으면 `y` 를 누릅니다.

   ```bash
   npm run push
   ```

   push 는 원격 프로젝트의 파일을 `gas/` 구성으로 통째로 바꿉니다(원격의 기본 `Code.gs` 도 사라짐).
7. 브라우저에서 <https://script.google.com> → `HDS 안전장부` 프로젝트를 열고, `Setup.gs` 를 연 상태로
   [(A) 방법의 9~11단계](#5-배포-방법-a-붙여넣기)대로 `setup` 을 실행하고 권한을 승인한 뒤, 로그의 관리자 비밀번호를 적어 둡니다.
8. 웹앱으로 배포합니다. 웹앱 설정(실행: 나, 액세스: 모든 사용자)은 `gas/appsscript.json` 에 들어 있습니다. `npm run deploy` 로 해도 됩니다.

   ```bash
   clasp deploy -d "v1.0.0"
   ```

9. 배포 ID 와 주소를 확인합니다. `@HEAD` 가 아닌 줄이 방금 만든 배포입니다. 웹앱 주소는 `https://script.google.com/macros/s/<배포 ID>/exec` 입니다.

   ```bash
   clasp deployments
   ```

   편집기의 **배포** → **배포 관리**에서도 같은 주소를 볼 수 있습니다. 처음 한 번은 편집기에서 열어 액세스가 **모든 사용자**인지 눈으로 확인하십시오.

- clasp 3 에서는 같은 명령이 `create-deployment`(= deploy), `list-deployments`(= deployments) 이름으로도 있습니다.
- `.clasp.json` 에는 스크립트 ID 만 들어 있습니다. 로그인 정보는 홈 폴더의 `~/.clasprc.json` 에 저장되니 이 파일은 절대 저장소에 넣지 마십시오.
- 붙여넣기로 설치한 프로젝트에 clasp 를 써도 됩니다. 다만 push 하면 파일 구성이 `gas/` 로 바뀌니, 그 뒤로는 계속 clasp 로 관리합니다.
- 이미 배포한 뒤 주소를 유지하며 갱신하는 방법은 [14. 업데이트 방법](#14-업데이트-방법)을 보십시오.

## 7. 처음 설정

1. **관리자 로그인** — 웹앱 주소를 열고 아이디 `admin`, 로그의 임시 비밀번호로 들어갑니다.
2. **비밀번호 변경** — 설정 → 비밀번호 변경. 임시 비밀번호는 바로 바꿉니다. 새 비밀번호는 8자 이상, 영문과 숫자를 함께 넣습니다.
3. **회사·메일 설정** — 설정에서
   - 회사명(처음 값 `HDS(주) 안전경영지원실`)
   - **본사 메일**: 사고·작업중지 단계 보고 즉시 알림, 매일 기한경과 조치 요약, 매주 요약을 받을 주소(여러 개 가능)
   - 메일 종류별 켜기·끄기(새 요청, 반려, 사고 알림, 매일 독촉, 주간 요약)
   - 독촉 시점(처음 값: 마감 3일 전·1일 전, 기한경과), 일일점검 마감 시각(처음 값 10:00), 월간보고 마감일(처음 값 5일)
   - 필수 양식 기본값
4. **트리거 설치** — [8. 트리거 설치](#8-트리거-설치자동-메일).
5. **본사 사용자 추가** — 사용자 화면에서 본사 담당(hq)·열람(viewer) 계정을 만듭니다. 관리자도 한 명 더 만들어 두면 비밀번호를 잊었을 때 서로 재설정할 수 있습니다.
6. **사업장 등록** — 사업장 → 새 사업장.
   - 사업장 ID: 영문 대문자·숫자 2~8자(예: `S001`). 기록 번호에 들어가므로 나중에 바꾸지 않습니다.
   - 이름·유형·지역·고객사·주소·근무조
   - **담당자 이름·이메일·전화**: 요청·반려·독촉 메일이 이 이메일로 갑니다
   - HEC 평가 대상 여부와 최근·다음 평가일(분석의 HEC 준비도에 쓰임)
   - 필수 양식(비우면 설정의 기본값)

   저장하면 사업장 링크가 자동으로 만들어집니다.
7. **인원 명부** — 사업장 상세의 인원에서 등록합니다. 여러 명을 한 번에 등록할 수도 있고, 사업장 담당자가 직접 해도 됩니다.
8. **링크·QR 전달** — 사업장 상세에서 링크 복사 또는 QR 을 내려받아 **담당자에게 개별로** 전달합니다. 필요하면 PIN 을 정합니다([13. 보안](#13-보안)).
9. **요청 보내기** — 배포·요청 → 새 요청 → 양식·대상 사업장·기간·마감일을 정해 보냅니다. 대상 사업장 담당자에게 메일이 갑니다.

> **예시 데이터 주의** — 설정의 "예시 데이터 불러오기"는 교육·시연용 가상 사업장·기록을 넣으면서 **기존 데이터를 모두 바꿉니다**.
> 운영 중에는 쓰지 마십시오. 운영 전에 써 봤다면 실제 사업장을 등록하기 전에 설정의 데이터 비우기(사용자·세션은 남음)로 지웁니다.

## 8. 트리거 설치(자동 메일)

자동 독촉·요약 메일은 시간 트리거로 돕니다.

| 함수 | 언제 | 하는 일 |
|---|---|---|
| `cronDaily` | 매일 오전 8시대 | 마감 D-3·D-1·기한경과 요청과 정기 양식 미제출 사업장에 독촉, 기한경과 '높음' 조치 요약을 본사 메일로 |
| `cronWeekly` | 매주 월요일 오전 8시대 | 주간 요약(제출률·사고·미결 조치)을 본사 메일로 |

**설치**: 관리자로 로그인 → 설정 → 트리거 설치. 설정의 시스템 정보에 설치된 트리거가 보입니다.

**편집기에서 직접 설치할 때**: 왼쪽 시계 아이콘 **트리거** → **트리거 추가** →
`cronDaily` / 이벤트 소스 **시간 기반** / **일 단위 타이머** / **오전 8시~9시**, 그리고
`cronWeekly` / **시간 기반** / **주 단위 타이머** / **매주 월요일** / **오전 8시~9시**. 같은 함수의 트리거가 두 개가 되지 않게 합니다.

- 구글 시간 트리거는 지정한 한 시간 안의 어느 때에 돕니다(정각 보장 아님).
- 트리거는 설치한 계정 권한으로 돌고, 메일도 그 계정 이름으로 나갑니다. 앱을 올린 계정으로 설치하십시오.

## 9. AI 요약(선택)

분석 화면의 발견 문장은 규칙으로 만들어져 키 없이도 나옵니다. 여기에 더해 Claude API 로 분석 요약 문단을 받으려면 키를 넣습니다.

1. Claude Console(<https://platform.claude.com>)에서 API 키를 만듭니다. 사용량만큼 요금이 나오니 결제 정보와 사용 한도를 Console 에서 먼저 정해 둡니다.
2. Apps Script 편집기 → **프로젝트 설정** → **스크립트 속성** → **스크립트 속성 추가**
   - 속성: `ANTHROPIC_API_KEY`
   - 값: 받은 키
3. 저장하면 분석 화면에 AI 요약 버튼이 나옵니다. 키를 지우면 버튼이 사라집니다.
4. (선택) 모델을 바꾸려면 스크립트 속성 `ANTHROPIC_MODEL` 에 모델 ID 를 넣습니다. 비우면 `claude-opus-5-5` 를 씁니다.

- 보내는 것은 분석 화면이 계산한 **요약 숫자**(기간·사업장 범위의 건수·비율 등)입니다. 기록 원문·사진은 보내지 않습니다.
- 키는 스크립트 속성에만 저장되며, 이 프로젝트 편집 권한이 있는 사람만 볼 수 있습니다.

## 10. 미리보기와 시험

구글에 올리지 않고 컴퓨터에서 화면을 확인하는 방법입니다. Node.js 20 이상.

| 명령 | 하는 일 |
|---|---|
| `npm run build` | `gas/` 를 묶어 `dist/preview.html` 하나로 만듦(가짜 서버 내장) |
| `npm run paste` | `gas/` 를 묶어 `paste/` 붙여넣기 파일 6개(+안내 메모)를 다시 만듦. `gas/` 를 고친 뒤에는 꼭 다시 실행 |
| `npm run check` | 붙여넣기 배포 규칙 검사: `'<?'`·`'?>'` 문자열, import/export·require, 다른 파일 객체를 최상위에서 바로 부르는 코드(파일 순서 의존), 전역 이름 충돌, `paste/` 가 `gas/` 최신인지 |
| `npm test` | Node 에서 서버 시나리오 시험(setup → 로그인 → 사업장 → 기록 저장·제출·반려·재제출·확인 → 조치 → 요청·독촉 메일 → 내보내기 → 권한 위반 거부). `.gs` 를 GAS 처럼 파일마다 따로(역순으로) 올리는 단계 포함 |
| `npm run test:paste` | `paste/` 를 다시 만든 뒤 `paste/Code.gs` 를 올려 같은 시나리오 시험(붙여넣기 묶음이 그대로 동작하는지) |
| `npm run e2e` | Playwright(Chromium)로 미리보기를 열어 모든 화면을 1440·768·390px 폭으로 확인, 스크린샷 `dev/shots/` |
| `npm run push` | `gas/` 를 Apps Script 로 올림(clasp) |
| `npm run deploy` | 웹앱 배포(clasp) |

미리보기 만들기:

```bash
npm run build
```

`dist/preview.html` 을 브라우저로 엽니다(파일을 더블클릭). 저장소에 이미 만들어진 파일이 들어 있어 빌드 없이 열어도 됩니다.

- 처음 열면 가짜 서버가 자동으로 setup 하고 관리자 **`admin` / `hds1234`** 를 만듭니다. 이 비밀번호는 **미리보기 전용**입니다. 실제 배포의 관리자 비밀번호는 setup 로그에 나온 임의 값입니다.
- 주소 끝에 `?demo=1` 을 붙이면(예: `file:///…/dist/preview.html?demo=1`) 자동 로그인하고, 데이터가 없으면 예시 데이터(사업장 12곳, 약 90일 치)를 넣습니다.
- 사업장 화면을 보려면 사업장 상세의 링크에 있는 `?s=<토큰>` 을 미리보기 주소 뒤에 붙여 엽니다.
- 미리보기 데이터는 그 브라우저의 localStorage(`hds-preview-db`)에만 저장됩니다. 처음부터 다시 하려면 브라우저 개발자 도구에서 이 항목을 지웁니다.
- 메일은 실제로 나가지 않습니다.

서버 시험:

```bash
npm test
```

화면 시험(Playwright 와 Chromium 이 필요합니다):

```bash
npm run e2e
```

Chromium 이 없다고 나오면 한 번 설치합니다.


## 11. 데이터 저장 위치

모두 앱을 올린 계정의 구글 드라이브에 있습니다. 바로 가기: 설정 → 시스템 정보(DB 시트·파일 폴더 열기).

**구글 시트 `HDS 안전장부 DB`** — 테이블 하나가 시트 하나, 1행은 영문 열 이름입니다.

| 시트 | 담는 것 |
|---|---|
| `sites` | 사업장(이름·유형·지역·고객사·근무조·필수 양식·HEC·담당자 연락처·링크 토큰·PIN 해시) |
| `people` | 사업장 인원 명부(이름·직무·역할·전화 끝 4자리) |
| `users` | 본사 사용자(아이디·이메일·역할·비밀번호 해시) |
| `sessions` | 로그인 세션 |
| `records` | 양식 기록 1건 = 1행. 상태·단계·작성자·검토 이력, `facts`(분석용 요약), `data`(입력 내용 JSON) |
| `acts` | 조치대장(출처 기록·항목·위험도·기한·담당·상태·전후 사진·이력) |
| `requests` | 본사가 보낸 요청·공지(대상·양식·기간·마감·첨부·독촉) |
| `reads` | 요청·공지 열람·확인 기록 |
| `files` | 사진·서명·첨부 목록(실제 파일은 드라이브) |
| `log` | 활동·메일 발송 기록 |
| `kv` | 설정·번호 카운터 |

- 날짜·시각은 글자(`YYYY-MM-DD`, `YYYY-MM-DDTHH:mm:ss`, 한국 시간)로 저장합니다.
- 큰 입력 내용은 4만 5천 자씩 `data`, `data_2` … `data_8` 열에 나눠 저장하고, 그래도 넘치면 드라이브에 JSON 파일로 저장한 뒤 `data` 에 `@drive:<파일 ID>` 를 적습니다.
- 지운 기록·조치는 행이 남고 `deleted` 가 TRUE 가 됩니다(기록 보존). 앱 화면에는 나오지 않습니다.

**분석 시트(`V_` 로 시작)** — 양식별로 기록 한 건을 한 행으로 펼친 시트와 월간 지표 시트입니다. 피벗 테이블이나 Looker Studio 로 따로 분석할 때 씁니다.
`records` 를 바탕으로 만든 사본이라 여기를 고쳐도 앱에는 반영되지 않고, 설정 → 뷰 재구축 때 덮어씁니다.

**드라이브 폴더 `HDS 안전장부 파일`** — 사진·서명·첨부 파일과 큰 기록 JSON. 파일 이름이 아니라 `files` 시트의 ID 로 연결되니 폴더 안 파일을 옮기거나 지우지 마십시오.

**시트를 직접 고쳐야 할 때**: 가능하면 앱에서 고치십시오. 꼭 시트에서 고친다면 1행 열 이름과 열 순서를 바꾸지 말고, JSON 열은 올바른 JSON 으로,
날짜는 글자로 두고, `data_2` 이후 열과 `token`·`pwHash`·`salt`·`pinHash` 열은 건드리지 않습니다. 고치기 전에 **파일 → 사본 만들기**로 백업합니다.

## 12. 한도

Google Apps Script·Gmail 의 계정 한도가 그대로 적용됩니다.

| 항목 | 한도 | 이 앱에서 |
|---|---|---|
| 메일 수신자 | 하루 100명(개인 Gmail) / 1,500명(Google Workspace) | 요청·독촉·알림 메일이 모두 포함됩니다. 사업장이 많으면 Workspace 계정을 쓰십시오. 남은 양은 설정 → 시스템 정보 |
| 실행 시간 | 한 번에 6분 | 범위가 큰 내보내기는 기간·사업장을 나눠서 합니다 |
| 트리거 총 실행 시간 | 하루 90분(개인) / 6시간(Workspace) | 매일·매주 자동 작업 |
| 시트 셀 | 한 칸 50,000자 | 자동으로 나눠 저장(위 11번) |
| 스프레드시트 | 파일 하나 1,000만 셀 | 모든 시트 합계 |
| 파일 올리기 | 한 파일 8MB | 사진은 올리기 전에 긴 변 1600px 로 줄여 보냄 |

동시에 여러 명이 저장하면 서버가 잠금(최대 20초)으로 차례를 맞춥니다. 드물게 저장이 실패하면 잠시 뒤 다시 누르면 됩니다.

## 13. 보안

- **사업장 링크는 비밀번호와 같습니다.** 링크를 아는 사람은 그 사업장으로 기록을 쓰고 볼 수 있습니다. 단체방·게시판에 올리지 말고 담당자에게 개별로 보내십시오.
  QR 은 직원만 드나드는 곳에 둡니다.
- **링크 재발급** — 링크가 새었거나 담당자가 바뀌면 사업장 상세 → 링크 재발급. 예전 링크로는 더 이상 들어올 수 없으니 새 링크를 다시 전달합니다.
  이미 로그인해 둔 기기까지 바로 끊어야 하면 DB 시트 `sessions` 에서 그 사업장 행(`site` 열)을 지우십시오(서버 캐시 때문에 최대 6시간 걸릴 수 있음).
- **PIN** — 사업장 상세에서 PIN 을 정하면 링크 + PIN 이 있어야 들어옵니다. PIN 은 해시로만 저장되고, 15분 안에 5번 틀리면 15분 동안 잠깁니다. 비우면 해제됩니다.
- **실행 권한** — 웹앱은 "실행: 나"라서 모든 사용자의 요청이 앱을 올린 계정 권한으로 처리됩니다. 그 계정에 2단계 인증을 켜고, 비밀번호를 아는 사람을 최소로 하십시오.
  DB 시트를 다른 사람에게 편집 공유하면 앱 권한을 거치지 않고 모든 데이터를 볼 수 있으니, 본사 직원에게는 시트 대신 앱 계정(열람 역할 등)을 주십시오.
- **본사 계정** — 비밀번호는 솔트 + SHA-256 해시로만 저장합니다. 로그인을 15분 안에 5번 틀리면 15분 동안 잠깁니다. 비밀번호를 바꾸면 그 계정의 다른 기기 로그인은 끊깁니다. 로그인 유지 기간은 본사 14일, 사업장 30일이며, 공용 PC 에서는 로그아웃하십시오.
- **설치 순서** — `setup` 은 웹앱을 배포하기 **전에** 편집기에서 실행하십시오. 웹앱이 열린 뒤에는 화면 쪽에서 전역 함수(`setup`·`cronDaily`·`cronWeekly` 등)를 부를 수 있는 구조라,
  관리자 계정이 아직 없을 때 공개되면 남이 첫 관리자를 만들 수 있습니다. setup 이 한 번 끝나면 다시 불려도 관리자·데이터는 바뀌지 않고, 독촉·주간 요약 메일은 같은 날 같은 곳에 두 번 가지 않습니다.
- **메일 링크** — 메일의 "기록 보기"·반려 링크는 `…/exec?v=rec/<기록번호>`(사업장은 `?s=<토큰>&v=…`) 모양이라 앱이 열리면 그 기록으로 바로 갑니다.
- **개인정보** — 인원 명부에는 전화번호 끝 4자리만 둡니다. 분석용 요약(`facts`)에는 사람 이름과 민감 항목을 넣지 않습니다.

## 14. 업데이트 방법

웹앱 주소가 바뀌면 이미 보낸 사업장 링크·QR 이 모두 끊깁니다. 그래서 **새 배포를 만들지 말고 기존 배포의 버전만 올립니다.**

**(A) 붙여넣기**

1. 새로 받은 `paste/` 파일 중 바뀐 파일을 편집기의 같은 이름 파일에 **통째로** 다시 붙여넣고 저장합니다.
   어느 파일이 바뀌었는지 모르면 6개 모두 다시 붙여넣습니다.
2. **배포** → **배포 관리** → 지금 쓰는 배포 선택 → 연필(수정) 아이콘 → 버전: **새 버전** → 설명 입력 → **배포**.

**(B) clasp**

```bash
npm run push
```

```bash
clasp deployments
```

위에서 확인한 운영 배포 ID(`@HEAD` 가 아닌 것)를 넣어 같은 주소에 새 버전을 올립니다.

```bash
clasp deploy -i <배포 ID> -d "v1.0.1"
```

**개발 담당자** — 코드는 `gas/` 에서 고칩니다. `paste/` 는 직접 고치지 말고, 고친 뒤 다시 만들어 함께 커밋합니다.

```bash
npm run paste && npm run check && npm run test:paste
```

`check` 는 붙여넣기에서 깨지는 코드를 잡습니다: HTML·스크립트 안의 `'<?'`·`'?>'` 문자열(템플릿이 스크립틀릿으로 오해),
`import`/`export`·`require`, 한 `.gs` 파일의 최상위에서 다른 파일 객체를 바로 부르는 코드(편집기의 파일 순서에 따라 깨짐), 같은 전역 이름이 두 파일에 있는 것.

- 저장(또는 push)만 하고 새 버전을 배포하지 않으면 사용자 화면은 바뀌지 않습니다. 반면 트리거(자동 메일)는 저장된 최신 코드로 돌기 때문에 저장 즉시 반영됩니다.
- 배포 전에 확인하려면 **배포** → **배포 테스트**의 `/dev` 주소로 엽니다(프로젝트 편집 권한자만 열림).
- `appsscript.json` 의 권한이 바뀐 업데이트라면 편집기에서 `setup` 을 한 번 실행해 새 권한을 승인합니다(데이터는 그대로).
- 업데이트 후 설정 → 뷰 재구축을 한 번 눌러 분석 시트를 새 형식으로 맞춥니다.

## 15. 문제 해결 FAQ

**setup 실행 때 "Google에서 확인하지 않은 앱"이 나옵니다.**
직접 만든 스크립트라서 나옵니다. 고급 → 이동 → 허용을 누릅니다.

**편집기에 붙여넣고 저장하면 문법 오류가 납니다.**
파일이 덜 붙여넣어졌거나, 문서 프로그램을 거쳐 따옴표가 바뀐 것입니다. 텍스트 편집기에서 다시 전체 복사해 그 파일 내용을 통째로 바꿉니다.

**함수 목록에 `setup` 이 없습니다.**
함수 목록은 지금 열린 파일의 함수만 보여 줍니다. 붙여넣기로 설치했으면 `Code.gs`, `gas/` 파일로 설치했으면 `Setup.gs` 를 열고 고릅니다.

**앱을 열었더니 "설치가 끝나지 않았습니다"라는 안내가 나옵니다.**
편집기에서 `setup` 을 실행하지 않았거나 실행이 끝나지 않은 것입니다. [(A) 방법의 9~11단계](#5-배포-방법-a-붙여넣기)를 합니다.

**앱을 열면 HTML 파일을 찾을 수 없다는 오류가 나옵니다.**
HTML 파일 이름이 다릅니다. 붙여넣기로 설치했으면 `Index`·`Styles`·`App`·`FormsData` 네 개가 대소문자까지 맞는지 보고, 고친 뒤 새 버전으로 배포합니다.

**앱 화면 위에 이 앱을 구글이 아닌 Apps Script 사용자가 만들었다는 안내 띠가 보입니다.**
개인 구글 계정으로 배포한 웹앱에 구글이 붙이는 안내입니다. 동작에는 영향이 없습니다.

**관리자 임시 비밀번호를 적지 못했습니다.**
setup 은 처음 한 번만 비밀번호를 보여 줍니다. 다른 관리자 계정이 있으면 사용자 화면에서 재설정합니다. 그래서 운영 전에 관리자를 두 명 만들어 두기를 권합니다.

**사업장 링크를 열면 구글 로그인 화면이 나옵니다.**
배포의 액세스가 "모든 사용자"가 아니거나, `/exec` 가 아니라 `/dev` 주소를 보냈을 때입니다. 배포 관리에서 액세스를 확인합니다.
Google Workspace 계정이면 관리 콘솔 정책 때문에 "모든 사용자"를 고를 수 없을 수 있으니 Workspace 관리자에게 외부 공유 허용을 요청합니다.

**"구글 계정으로" 로그인이 안 됩니다.**
앱을 올린 계정과 같은 Workspace 도메인 계정이어야 하고, 사용자 화면에 그 이메일이 등록돼 있어야 합니다. 아니면 아이디·비밀번호로 로그인합니다.

**로그인이 잠겼습니다.**
15분 안에 5번 틀리면 15분 동안 잠깁니다. 기다린 뒤 다시 하거나 관리자에게 비밀번호 재설정을 요청합니다.

**메일이 오지 않습니다.**
받은편지함의 스팸함 → 설정의 메일 켜기·끄기 → 사업장 담당자 이메일 → 설정 → 시스템 정보의 남은 메일 수 순서로 확인합니다. 보낸 메일 기록은 DB 시트 `log` 에도 남습니다.

**독촉·주간 요약 메일이 나가지 않습니다.**
트리거가 설치됐는지 편집기 왼쪽 **트리거** 화면에서 `cronDaily`·`cronWeekly` 를 확인합니다. 실패 이유는 왼쪽 **실행** 화면의 기록에서 볼 수 있습니다.

**"Exceeded maximum execution time" 오류가 납니다.**
한 번 실행 6분 한도를 넘은 것입니다. 내보내기라면 기간이나 사업장을 나눠서 합니다.

**"Service invoked too many times for one day: email" 오류가 납니다.**
하루 메일 한도를 넘은 것입니다. 다음 날 풀립니다. 사업장이 많으면 Workspace 계정으로 옮기거나 독촉 메일 종류를 줄입니다.

**사진이 올라가지 않습니다.**
한 파일 8MB 이하인지, 휴대폰 브라우저에 카메라·사진 접근을 허용했는지, 통신이 안정적인지 확인합니다.

**코드를 고쳤는데 화면이 그대로입니다.**
새 버전을 배포하지 않은 것입니다([14. 업데이트 방법](#14-업데이트-방법)). 배포했다면 브라우저를 새로 고칩니다.

**사업장 링크로 들어가면 "사업장 링크가 맞지 않거나 바뀌었습니다"가 나옵니다.**
누가 링크를 재발급했거나, 링크 일부가 잘려 전달된 경우입니다. 사업장 상세에서 현재 링크를 다시 전달합니다.
링크를 열었는데 앱 자체가 열리지 않으면 새 배포를 만들어 웹앱 주소가 바뀐 것입니다. 원래 배포에 새 버전으로 올리고([14번](#14-업데이트-방법)), 이미 바뀌었다면 모든 사업장에 새 링크를 보냅니다.

**사업장 링크로 들어가면 "운영이 끝난 사업장입니다"가 나옵니다.**
그 사업장의 상태가 '종료'입니다. 다시 쓰려면 관리자가 사업장 상세에서 상태를 '운영'으로 바꿉니다.

**확인된 기록을 고쳐야 합니다.**
확인된 기록은 잠깁니다. 관리자가 기록 상세에서 확인 취소 → 반려(사유 적기) → 사업장이 고쳐 다시 제출합니다.

**지운 기록이 시트에 남아 있습니다.**
정상입니다. 지우면 `deleted` 만 TRUE 로 바뀌고 앱에서는 보이지 않습니다.

**분석 숫자가 기록과 맞지 않습니다.**
분석 화면은 앱에 있는 기록으로 바로 계산합니다. 기간·사업장 필터를 확인하고 화면을 새로 고칩니다.
구글 시트의 `V_` 시트 숫자가 앱과 다르면 설정 → 뷰 재구축을 누릅니다.

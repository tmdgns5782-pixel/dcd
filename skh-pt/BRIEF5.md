# 5장 압축판 브리프 (BRIEF.md의 추가 지침)

**BRIEF.md 전체를 먼저 읽는다.** PPTX 변환 제약(§2), 디자인 원칙(§3), 숫자 규칙(§4), 그림 자산(§5), 원고(§6)는 그대로 유효하다.
이 문서는 **12장 판을 5장으로 압축**하는 규칙만 더한다. 의뢰인 구성안의 '1장~5장'이 원래 장당 한 쪽 구성이었다.

## 파일
- 틀(수정 금지): `src/deck5.html`. 슬라이드 id는 `t1`~`t5`. 머리글(장 번호·장 이름·질문, 헤드라인)·5장 진행 표시·바닥글(연구 제목·직무·지원자, 쪽수)은 이미 들어 있다. 표지는 없다.
- 너의 파일: `src/parts/t{N}.html`. CSS는 `#t{N}` 범위로, SVG id는 `t{N}-` 접두사로.
- 참고용 12장 판 원본: `src/parts/s1.html` ~ `s12.html`, 미리보기 `preview/deck-1.png` ~ `deck-12.png`. 이미 검토를 거친 디자인이므로, 부품·도식·차트는 **가져다 쓰되 `#sN`을 `#tN`으로, `sN-` id를 `tN-`로** 바꾼다.
- 미리보기: `node tools/preview-part.cjs deck5 {N}` → `preview/parts/deck5-{N}.png` ("issues: none"이어야 함).

## 압축 원칙
- 장마다 본문은 1728×762px 한 면. 내용이 늘어나도 **본문 19px, 캡션 16px, 출처 13px 아래로 줄이지 않는다.** 줄어들어야 할 것은 글자 크기가 아니라 **문장 길이와 부가 요소**다.
- 시선이 머무는 곳은 장마다 1~2곳. 나머지는 보조로 낮춘다.
- 12장 판에서 **빼도 되는 것**은 아래 '빼도 됨'에 적었다. 그 밖의 숫자·핵심 문장은 남긴다.
- 장 핵심 메시지(.keybar)는 1·2·5장에. 3장은 헤드라인이 핵심 메시지이고, 4장은 '최종 BIM 생성 379/406(생성 완성도 93.3%)' 영웅 수치가 핵심 메시지다.

## 장별 구성
### t1 · 1장 연구 배경 및 문제 정의 (12장 판 S3 + S4)
- 세 덩어리를 한 장에, 왼쪽→오른쪽 또는 위→아래로 '정책 → 현실 → 문제' 흐름:
  ① 정책: 국토교통부 BIM 전면 도입 추진 — 공공공사 BIM 의무화 1,000억원 이상 신규 사업('22~'24 도로→철도·건축→하천·항만) → '26 500억원 이상 → '28 300억원 이상 / 2030 건축BIM 로드맵: '30 디지털 건축서비스 완전 구현. 출처 표기.
  ② 현실: 신규 건설 = 2D 도면을 먼저 그린 뒤 BIM으로 옮기는 'BIM 전환설계'가 대부분(추가 비용) / 기존 건축물 = BIM 없이 2D 도면만 → 새로 구축해야.
  ③ 문제: 사람이 도면을 보고 직접 모델링 → 노동집약적 작업 · 긴 작업 시간·높은 비용 · 휴먼 에러 가능성 (짧은 설명 한 줄씩)
- .keybar: "2차원 도면에 기반한 <em>3차원 BIM 모델 자동 생성 프로세스</em>가 필요합니다."
- 빼도 됨: LH 공동주택 의무화 비율, 비용 곡선 그래프(넣는다면 아주 작게), 도면 묶음 그림(작은 썸네일 정도는 가능), '결국 BIM을 만들려면…' 결론 줄(키바가 대신함).

### t2 · 2장 기존 연구 한계 및 연구 목표 (S5)
- S5와 같은 내용·구조(3행 한계 → 목표, 1:1 대응) + .keybar(2장 핵심 메시지). S5를 그대로 옮기되 t2 범위로. 필요하면 다듬기만.

### t3 · 3장 연구 방법 (S6 + S7 + S8 요점)
- 4단계 가로 흐름(STEP 1 도면 이미지 입력 → 2 객체 인식 → 3 대응 객체 매칭 → 4 BIM 자동 생성), 단계마다 그림(step1~4.png) + 이름 + 한 줄 설명 + 핵심 기법 칩.
- 단계별로 S7·S8의 '어떻게'를 한 줄씩 보강(쉬운 말):
  STEP 2: 평면도 → 방향별(동·서·남·북) 외벽 창·문 정리 / 입면도 → DBSCAN으로 같은 층끼리 묶어 층 높이 파악. 기법: YOLO + SAHI(작은 객체 분할 추론), DBSCAN
  STEP 3: LMM(GPT-4o)이 도면 축척을 읽어 픽셀 → 실제 길이(예: 1 px = 33.88 mm) / 평면도의 X·Y + 입면도의 Z를 헝가리안 알고리즘으로 1:1 매칭. 기법: LMM 축척 보정, 헝가리안 알고리즘
  STEP 4: 골격선(스켈레톤)으로 벽 중심선 추출, 창·문을 붙일 벽(호스팅) 결정 → Revit API로 BIM 생성. 기법: 스켈레톤 기반 벽체 추출, Revit API
- 빼도 됨: plan-parsing / elev-parsing / bim-instantiation 상세 스트립, 매칭 개념도(넣는다면 STEP 3 그림을 대신하는 정도), 비용 행렬 3단계 설명, 축척 보정 예시 도식(수치 한 줄로 대체).

### t4 · 4장 연구 결과 및 기여 (S9 + S10 요점)
- S9 구조(기여 3 → 근거 수치 3, 오른쪽 영웅 수치 379/406 · 생성 완성도 93.3% + 결과 BIM 그림)를 기본으로.
- S10에서 신뢰도를 주는 요소만 작게 보강(선택): 검증 규모 한 줄 — 학습 이미지 평면도 72,792장 · 입면도 16,992장(타일 포함) / 매칭 8개 동 개구부 3,458개 / BIM 생성 건물 1동. 근거 수치 옆 비교값(Baseline 0.507·0.355, Tesseract OCR 0.369)은 유지.
- 지표 풀이 한 줄(mAP@0.5 · F1-score · LMM)은 하단에 유지.
- 빼도 됨: 층별 클러스터링 ARI/NMI/Homogeneity, EasyOCR 막대, 요소별 생성 막대(벽 135/153 등 — 영웅 카드 안 한 줄로 축약 가능), 체적 IoU.

### t5 · 5장 직무와의 연관성 (S11 + S12 요점)
- S11 구조(직무 과제 3 ↔ 연구 접점 3) + .keybar(제안 문구: "도면 속 불완전한 정보를 <em>정확한 3D 데이터</em>로 잇는 경험으로, SK하이닉스 Virtual FAB의 데이터 품질을 높이겠습니다.").
- 마지막 장이므로 아주 작게 게재 정보 한 줄 + 감사 인사를 넣어도 좋다(예: 오른쪽 아래 'Automation in Construction · Vol. 187 · 2026 게재' 배지, 또는 키바 아래 작은 '감사합니다'). 과하지 않게.

## 2. PPTX 변환 제약 (반드시 — 어기면 PPT가 깨진다)
- 글자는 HTML 텍스트로만. SVG `<text>` 금지. 글자 그라데이션(background-clip:text) 금지.
- CSS `transform`은 이동(translate)만. 회전·기울이기·확대 금지.
- HTML 요소에 `clip-path`, `mask`, `filter`, `backdrop-filter`, `mix-blend-mode` 금지.
- SVG는 path/line/circle/ellipse/rect/polygon/polyline + 단색·선형 그라데이션 + stroke-dasharray까지 지원. `<filter>`, `<mask>`, `<pattern>`, 방사형 그라데이션, clipPath(원∩원 외) 금지.
- CSS 배경: 단색·linear-gradient·radial-gradient OK. box-shadow OK(부드러운 그림자 1개 위주). 테두리·모서리 반경 OK. ::before/::after OK.
- 사진·그림(img)은 고해상도 그림으로 들어간다(object-fit: cover/contain OK).
- 차트는 **HTML 막대(div) 또는 SVG 도형**으로 직접 그린다(그림 파일 금지). 수치 라벨은 HTML 텍스트.

## 3. 디자인 원칙
- **색**: 흰 바탕 + 딥 네이비(--navy) 구조 + **SK Red(--accent)는 핵심 수치·제안 방법·헤드라인 강조에만**(화면 면적 5% 이하). 비교군·기준값은 회색(--gray-bar, --gray-bar-2). 주황은 로고에만. 카드 면은 --surface.
- **글자**: 본문 22px(최소 19px), 블록 제목 26~32px, 캡션 16px, 출처 13px. 핵심 수치 56~96px(--kpi). 한 블록에 크기 3단계 이내.
- **격자**: 본문 폭 1728px. 열 사이 간격 32~48px, 카드 안쪽 여백 28~36px, 8px 배수. 모서리 반경 20(카드)/12(그림). 정렬선 통일.
- **위계**: 장마다 시선이 머무는 곳 1~2곳. 꽉 채우지 말고 숨 쉬는 여백. 하지만 휑하지 않게.
- **연구 그림**은 흰 틀(.fig) 안에, 그림 아래 캡션(.cap). 외부 자료는 출처(.src) 필수.
- 장 핵심 메시지(.keybar)는 브리프가 정한 장에만(아래 원고에 표시).
- 아이콘: 선 아이콘(굵기 2, 끝 둥글게), 크기 24~40px, 색은 네이비 또는 ink-3.

### S5 02 기존 연구 한계 ↔ 연구 목표 (1:1 대응이 한눈에)
- 3행 × [한계 → 목표]. 행마다 쟁점 이름 표시.
  1 높이 정보 — 한계: 평면도 한 장만 사용 → 높이 정보를 알 수 없음(수동 입력·고정값) / 목표: **평면도와 입면도 정보를 통합**해 완전한 3차원 BIM 생성
  2 CAD 의존 — 한계: CAD 레이어·블록 같은 정보에 의존 → 이미지로만 남은 실제 도면에는 적용 불가 / 목표: **CAD 정보 없이 이미지만으로** 평면도·입면도 간 대응 객체 정의
  3 치수 의존 — 한계: 치수 글자 인식(OCR)에 의존 → 치수가 빠지거나 겹치면 부정확 / 목표: **LMM(대형 멀티모달 모델)으로 축척을 인식**해 안정적으로 치수 보정
- **.keybar (2장 핵심 메시지)**: "딥러닝 기반 도면 객체 인식과 평면도·입면도 간 직접 매칭으로, <em>정확한 3차원 정보를 가진 BIM 자동 생성 방법</em>을 제안합니다."

### S6 03 연구 방법 — 전체 프레임워크 (헤드라인이 3장 핵심 메시지)
- 4단계 가로 흐름, 단계마다 그림(step1~4) + 단계 이름 + 한 줄 설명 + 핵심 기법 칩:
  STEP 1 도면 이미지 입력 — 평면도·입면도 이미지(래스터)만 입력
  STEP 2 객체 인식 — 도면 속 벽·창문·문 인식 / 기법: YOLO + SAHI(작은 객체 분할 추론), DBSCAN 층별 클러스터링
  STEP 3 대응 객체 매칭 — 평면도와 입면도에서 같은 객체끼리 짝짓기 / 기법: LMM 기반 축척 보정, 헝가리안 알고리즘(최적 1:1 매칭)
  STEP 4 BIM 자동 생성 — 높이까지 갖춘 3D BIM 모델 / 기법: 스켈레톤 기반 벽체 추출, Revit API
- 단계 1~2 = '도면 해석', 3~4 = '3D 재구성'처럼 두 묶음 표시해도 좋음. 다음 두 장(S7: STEP 2 + 축척 보정, S8: STEP 3·4)으로 이어짐을 작게 표시.

### S7 03 연구 방법 — ① 도면 객체 인식 · 축척 보정
- 세 블록:
  (a) 평면도 인식 — plan-parsing.png: 평면도 객체 인식 → 최외곽 윤곽선 추출 → 방향별(동·서·남·북) 최외곽 개구부 정의. 의미: "외벽의 창·문을 방향별로 정리해 입면도와 짝지을 준비"
  (b) 입면도 인식 — elev-parsing.png: 입면도 객체 인식 → DBSCAN 층별 클러스터링(같은 층의 창·문끼리 묶어 층 높이 파악)
  (c) 축척 보정 — LMM(GPT-4o)이 도면의 축척·용지 크기를 읽어 픽셀을 실제 길이로 변환. 예시: 도면 이미지 4,963×3,509px · 축척 1/200(A3) → 1 px = 33.88 mm. (scale-calib-ref.png는 'LLM' 오기가 있으니 쓰지 말고 HTML/SVG로 다시 그림)
- 기법 칩: YOLO + SAHI / DBSCAN / LMM(GPT-4o)

### S8 03 연구 방법 — ② 대응 객체 매칭 · BIM 생성
- (a) 대응 객체 매칭: matching-concept.png — 평면도에서 X·Y 좌표, 입면도에서 Z 좌표(높이). 설명: 객체 위치·상대 정렬로 비용 행렬 구성 → 헝가리안 알고리즘으로 최적 1:1 매칭 → 같은 창·문의 3차원 위치 확정. 그림의 영문 라벨 옆에 한국어 보조 라벨을 HTML로 덧붙여도 좋음.
- (b) BIM 요소 생성: bim-instantiation.png 5단계(평면도 객체 인식 결과 → Skeletonization(골격선 추출) → 스켈레톤 기반 벽체 중심선·코너점 추출 → 창문 호스팅 관계 정의 → 문 호스팅 관계 정의) → Revit API로 BIM 모델 생성 → step4.png(결과 BIM).
- '호스팅' = 창·문을 어느 벽에 붙일지 정하는 것(쉬운 말로).

### S9 04 연구 결과 및 기여 — 기여 ↔ 근거 수치 (이 장의 핵심)
- 3행 × [기여 → 근거 수치]. 기여와 수치가 짝지어 보이게:
  기여 1 도면 종류별 최적 학습·인식 전략 제안 → 평면도 mAP@0.5 **0.934** (+42.7%p) · 입면도 mAP@0.5 **0.838** (+48.3%p) — Baseline 대비
  기여 2 CAD 정보 없이 평면도·입면도 간 객체 대응 관계 정의 → 매칭 F1-score 창문 **0.93** · 문 **0.95**
  기여 3 LMM 기반 축척 인식으로 불완전한 도면에서도 안정적인 치수 보정 → 축척 인식 정확도 **0.707** (Tesseract OCR 대비 +33.8%p)
